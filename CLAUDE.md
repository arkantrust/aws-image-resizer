# CLAUDE.md

Guidance for agents working in this repo. Keep this file current: when you
change the architecture, bucket layout, routes, or dev workflow described
below, update this file in the same change.

## What this is

An image gallery. Browser uploads a photo → Bun server hands out a presigned
S3 PUT URL → browser PUTs the raw file directly to S3 → browser tells the
server the upload is done → server downloads the raw object, converts it to
WebP with `Bun.Image`, writes `<uuid>.webp` back to S3, deletes the raw
object, and appends the uuid to `index.txt`. The gallery page reads
`index.txt` (via the server) to know which images to render.

`apps/resizer` is a separate, not-yet-wired-up app. Leave it alone unless
asked to work on it specifically.

## Repo layout

- `infra/` — the entire Pulumi program (its own `Pulumi.yaml`, `package.json`, `tsconfig.json`; `pulumi` commands run from inside this directory, not the repo root).
  - `infra/index.ts` — entry point, instantiates `ImageBucket`.
  - `infra/imageBucket.ts` — `ComponentResource` provisioning the S3 bucket, its policies, and an IAM user scoped to it. Imported as `./imageBucket` (sibling of `index.ts`, not nested under another `infra/`).
  - `infra/scripts/sync-env.ts` — writes `apps/web/.env` from `pulumi stack output`; run as `bun run sync-env` from inside `infra/` (that's where its `package.json` script lives).
- `apps/web` — the app itself:
  - `src/index.ts` — Bun.serve backend (API routes + serves the React app via HTML import).
  - `src/App.tsx`, `src/components/UploadForm.tsx`, `src/components/Gallery.tsx`, `src/lib/api.ts` — frontend.
  - `src/components/ui/*` — shadcn/ui primitives (new-york style, see `components.json`).
- `apps/resizer` — untouched, out of scope for now.

The repo root itself has no `package.json` — it's just `apps/`, `infra/`,
and top-level docs. Don't expect `bun run <script>` to work from the repo
root; `cd infra` (or `cd apps/web`) first.

## S3 bucket layout

- `tmp/<uuid>` — raw browser upload, **private**, auto-expires after 1 day (S3 lifecycle rule) as cleanup for abandoned uploads.
- `<uuid>.webp` — server-converted image, **publicly readable**. The bucket policy grants `s3:GetObject` on `*.webp` only — raw uploads under `tmp/` never end in `.webp`, so they can't be matched by that policy no matter the path.
- `index.txt` — newline-separated list of published uuids, **private**; only read/written through the app's IAM credentials, never directly by the browser.

Bucket name is auto-generated by Pulumi (not hardcoded) to avoid global-name collisions.

## Backend API (`apps/web/src/index.ts`)

- `POST /api/uploads/presign` — body `{ contentType }` (must start with `image/`). Returns `{ uuid, uploadUrl }`, a presigned PUT URL for `tmp/<uuid>` valid 5 minutes.
- `POST /api/uploads/:uuid/complete` — converts `tmp/<uuid>` to `<uuid>.webp` via `Bun.Image`, deletes the raw object, appends to `index.txt`. Returns `{ uuid, url }`.
- `GET /api/images` — returns `{ images: [{ uuid, url }] }` from `index.txt`.

The frontend's Content-Type header on the PUT must match the `contentType`
passed to `/presign` — it's part of the presigned URL's signature.

## Dev workflow

```bash
cd infra
pulumi preview
pulumi up
bun run sync-env              # writes ../apps/web/.env from the stack outputs
cd ../apps/web && bun install && bun dev
```

`sync-env` resolves both the Pulumi CLI's working directory and the `.env`
output path from the script's own file location (`import.meta.dir`), not
`process.cwd()` — so it also works if invoked some other way (e.g.
`bun run infra/scripts/sync-env.ts` from the repo root). Still, `bun run
sync-env` itself only resolves as an npm-style script from inside `infra/`
(or a subdirectory of it), since that's the only `package.json` that
declares it.

The web app reads `AWS_REGION` / `AWS_BUCKET` / `AWS_ACCESS_KEY_ID` /
`AWS_SECRET_ACCESS_KEY` from `apps/web/.env` (see `.env.example`). Bun's
`S3Client` also honors these exact env var names by default, but the backend
constructs an explicit client rather than relying on the global `Bun.s3` so
the missing-bucket error is clear.

Both `infra/` and `apps/web` typecheck with `bunx tsc --noEmit` (run from
their respective directories) — do that after any change.

## Known limitations (by design, not oversights)

- `index.txt` is read-modify-write with no locking: concurrent uploads
  completing at the same instant can race and drop one entry. Acceptable at
  this scope; revisit with a real index (DynamoDB, or S3 object listing
  instead of a manifest file) if concurrent uploads become common.
- No auth/rate-limiting on the upload endpoints. Anyone who can reach the
  server can upload. Fine for a local/personal project, not for anything
  public-facing without adding auth first.
- Single AWS region, one bucket, no CDN in front of the public images.

## Pulumi notes

- This project follows the `pulumi-best-practices` and `pulumi-component`
  skill guidance: outputs are passed directly between resources (no
  `apply()`-then-extract), `ImageBucket` is a `ComponentResource` with
  `parent: this` on every child and `registerOutputs()` at the end, and
  `pulumi.jsonStringify` builds IAM/bucket policy JSON from Outputs without
  manual `.apply()` nesting.
- CORS and lifecycle config use `aws.s3.BucketCorsConfiguration` /
  `aws.s3.BucketLifecycleConfiguration`, not the `*V2` variants — the V2
  resources are deprecated in the AWS provider and `pulumi preview` warns on
  them. Same shape (`bucket`, `corsRules`/`rules`), just the plain name.
- `pulumi preview`/`pulumi up` need a working connection to the configured
  Pulumi backend (Pulumi Cloud by default) and real AWS credentials. In one
  sandboxed agent environment, the `pulumi` CLI itself failed to reach
  `api.pulumi.com` (`connection reset by peer`) even though `curl` to the
  same host worked fine — a sandbox networking quirk, not a bug in this
  project. If you hit that, don't work around it with
  `pulumi login --local` or `PULUMI_CONFIG_PASSPHRASE` (that silently
  changes the user's backend); tell the user to run the Pulumi commands
  themselves instead.
- Bun's S3/Image API reference lives locally at
  `infra/node_modules/bun-types/docs/runtime/s3.mdx` and
  `.../docs/runtime/image.mdx` (also under `apps/web/node_modules/bun-types/`)
  — check there before guessing at the API.
- Root `.gitignore` uses unanchored `node_modules/`/`bin/` patterns (not
  `/node_modules/`) specifically so they still match `infra/node_modules`
  and `infra/bin` (tsc's `outDir`) now that the Pulumi program isn't at the
  repo root. Keep them unanchored if anything moves again.
